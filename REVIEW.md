# Ревью Lokit v0.5.1 — стабилизация видеопроцессора

Дата: 11 ноября 2026 года.

**Исправлено:**

1. Проверка выходных MP4 по видеосэмплам, дорожкам и фактическому диапазону показа через edit lists. Сырой `durationMs` включает скрытый преролл, поэтому его нельзя сравнивать напрямую с запрошенной длительностью.
2. Для фрагментированных MP4 `durationSec` анализатора может равняться нулю, хотя файл исправен. Проверки используют собранную длительность и реальное содержимое нового контейнера.
3. При инициализации резервного экспорта сбой Web Audio больше не приводит к тихому пропуску аудиодорожки.
4. Введён таймаут зависания декодера: 15 секунд без продвижения видеопозиции. Переход между клипами, повтор и перемотка сбрасывают счётчик.
5. Несовместимые MP4 (разная геометрия/кодек/наличие аудио) не объединяются «без перекодирования».

**Новые проверки:** 21 воспроизводимый синтетический видеообразец, 48 сценариев быстрых операций и резервных путей, включая 42 успешных lossless-результата. Внешняя проверка `ffprobe` сравнивает кодеки, длительности, наличие аудио, начало и продолжительность дорожек. `ffmpeg` полностью декодирует выходное аудио и видео. Набор форматов генерируется в GitHub Actions, не хранится в репозитории. 

**Ограничения:** эти образцы воспроизводят типичные свойства реальных файлов, но не заменяют проверку на пользовательских роликах; недостаточно покрыты большие файлы, редкие профили HEVC, HDR, VFR при сильных разрывах, дополнительные аудиодорожки, DRM и аппаратные декодеры Android TV.

# Ревью Lokit v0.5.0 — перенос обработки видео из выгрузки

Дата: 10 ноября 2026 года.

## Что взято из выгрузки

- `mp4-track-remux.js` — удаление аудиодорожки и изменение скорости MP4 без декодирования видео.
- `mp4-flatten.js` и `mp4-copy-trim.js` — сборка MP4 из исходных диапазонов байтов: точная обрезка с MP4 edit lists и склейка совместимых MP4.
- `webm-copy-trim.js` — обрезка WebM по ключевым кадрам.
- Визуальный редактор уже использует автономные `trim-timeline.js`, `waveform-preview.js` и `subtitle-serializer.js`.
- **Не включено:** FFmpeg/WASM, поскольку в архиве отсутствуют двоичные `.wasm`-ядра; общий WebCodecs видеотранскодер требует гарантированной корректной обработки аудио и контейнеров и не заменяет пока рабочий экспорт.

## Поведение

- Быстрые операции используют `File.slice()` + изменения контейнера и сохраняют исходные кодек и видеоданные; в WebM точный старт между ключевыми кадрами не обещается.
- Быстрая обрезка/склейка MP4 применяется только при исходном разрешении и совместимом формате; иначе срабатывает Canvas/MediaRecorder.
- Если при ускорении MP4 присутствует звук, не выполняется небезопасное изменение одних лишь видеотаймкодов — выбирается обычный экспорт со звуком.
- Для WebM есть выбор: точная обрезка с перекодированием либо быстрый режим, когда старт может быть раньше выбранного маркера. Предупреждение о смещении появляется в результате.
- Селектор «Размер по длинной стороне» заменён на «Разрешение итогового видео» с исходным, 360p, 480p, 720p, 1080p и 2160p. Цифра означает меньшую сторону изображения; маленькие источники не увеличиваются.
- Значение предыдущего пресета `width` не применяется к новой настройке `resolution`, чтобы не изменять его смысл молча.

## Локальные проверки

- `npm test` — определения 24 инструментов, редактор, локальная аналитика, настройки и их сброс, медиа, новые MP4/WebM fast paths, разрешения, HTML/PWA/номер версии: PASS.
- MP4 H.264/AAC 160×90: удаление звука сохраняет H.264; MP4 обрезка сохраняет видеодорожку и AAC; склейка двух файлов даёт длительность ~3 секунды.
- MP4 без аудио: изменение скорости 2× приводит к длительности примерно вдвое меньше.
- WebM VP8: точная обрезка в ключевом кадре выполняется без перекодирования; при начале между ключевыми кадрами происходит переход на точный экспорт или явное предупреждение для быстрого режима.
- Экспортные файлы проверялись `ffprobe` на совместимость контейнеров и длительность; браузерные сценарии требуют GitHub Actions.

## Непроверенные случаи

- Все комбинации кодеков, гигантские файлы, фрагментированные MP4, VFR/HDR, Android TV и аппаратные ограничения.
- Ключевые кадры WebM в большинстве файлов расположены редко; пользователь должен понимать, что ускоренная обрезка может начинаться раньше маркера.
- Проверьте лицензии и авторство импортированных компонентов перед распространением проекта за пределами личного сценария.
