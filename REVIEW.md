# Lokit — повторное ревью и исправления

Дата: 10 ноября 2026 года. Проверена текущая локальная сборка (главная страница, аналитика, Worker и тесты).

## Исправлено

1. **Гонка первой отправки аналитики:** при разрешении передачи пустая очередь ранее запускала пустую отправку, и последующие события могли остаться без отправки. Теперь при включении проверяется очередь, а после успешного завершения повторно проверяются события, добавленные во время запроса.
2. **Согласие пользователя:** отправка общей статистики по умолчанию отключена; включается явно. Отключение и очистка истории отменяют текущий HTTP-запрос и удаляют очередь отправки, если данные ещё не приняты сервером.
3. **Состояние общей статистики:** показывается адрес сервера, участие в сборе и число ожидающих событий. Неподключённый сервер отображается как недоступный, а не подставляет выдуманные цифры.
4. **Расчёт периодов:** личная и общая аналитика теперь используют одинаковые календарные периоды UTC; ранее скользящее 24-часовое окно могло отрезать часть первого дня.
5. **Срок хранения D1:** добавлена миграция индекса `0002_retention_index.sql`, ежедневный Cron Trigger и удаление событий спустя 90 дней после получения. Ранее очистка не выполнялась.
6. **Отмена запроса камеры/экрана:** интерфейс немедленно получает AbortError, даже если браузер держит открытым окно разрешения; при позднем согласии треки закрываются. Диалог разрешения невозможно программно закрыть во всех браузерах.
7. **Аудио разделённого экрана:** второй ролик дополнительно заглушён при предпросмотре/обработке, даже если первый подключён к аудиографу.
8. **Выбор кодека:** видео без звуковой дорожки использует MIME-профиль без аудиокодека; уменьшен риск ошибки экспорта без звука.
9. **Отмена чтения метаданных:** инструмент сведений о видео теперь передаёт AbortSignal в медиа-движок.
10. **Корректный учёт успеха:** успешная операция учитывается только после создания доступного пользователю результата; предыдущий результат удаляется при новом запуске, чтобы не спутать файлы.
11. **PWA:** новая версия кеша `lokit-v6`; Service Worker отвечает только за ресурсы Lokit из своего списка, не перехватывает другие пути на том же origin GitHub Pages.
12. **Доступность:** у фильтров и переключателей аналитики корректные `aria-pressed`, без неполной реализации ARIA tabs.
13. **UI:** уточнено, что обработка файлов локальная, а события общей статистики передаются только по согласию.

## Ограничения, которые невозможно закрыть только редактированием кода

1. **Браузерное сквозное тестирование:** Chromium в этом окружении блокирует даже `http://127.0.0.1` ошибкой `net::ERR_BLOCKED_BY_ADMINISTRATOR`; реальное воспроизведение и экспорт всех 24 инструментов в Chrome, Firefox и Android не подтверждены заново. Это не выдаётся за пройденный тест.
2. **Развёртывание общей аналитики:** рабочая D1 и Cloudflare Worker не созданы в аккаунте владельца, URL в `js/analytics-config.js` остаётся пустым. Серверные тесты выполнены на эмуляции D1 и SQLite.
3. **WAF / Cloudflare Rate Limiting:** API публичный, Origin не является гарантией против поддельных запросов. Для реального публичного проекта нужны правила в аккаунте Cloudflare и мониторинг (через одни лишь исходники гарантировать защиту нельзя).
4. **Ограничения форматов и реального времени:** медиаобработка использует возможности конкретного браузера (Canvas, WebAudio, MediaRecorder) и зависит от поддерживаемых кодеков, производительности и прав доступа.
5. **Общие показатели:** учитывают только посетителей, явно включивших отправку. Уникальные посетители не считаются; имя/IP/содержимое файлов в D1 не сохраняются.
