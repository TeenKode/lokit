# Lokit v0.8.2 beta — локальные инструменты

24 небольших инструмента для видео, аудио, субтитров, записи экрана и кадров. Сайт работает на GitHub Pages и сохраняет интерфейс офлайн.

## Пакетная обработка v0.6.0

Отдельная страница `batch.html` позволяет создать **общую очередь заданий для разных инструментов**, выбрать много файлов, задать параметры каждой группы и запустить последовательную обработку. Инструменты, которым нужны два файла, берут их парами в выбранном порядке. Запись камеры и экрана остаётся в обычном режиме.

У каждого задания видны состояние, процент (если его сообщает обработчик) и кнопка отмены. Общий процент считается **по числу заданий, а не по байтам**; при отсутствии прогресса отдельного инструмента его индикатор неопределённый. Есть пауза после текущего файла, отмена очереди, повтор ошибок и скачивание результатов по отдельности или одним ZIP.

ZIP создаётся прямо в браузере без внешнего CDN и без повторного сжатия видео, CRC32 рассчитывается блоками. Поддерживается формат ZIP32 до 4 ГБ. Выходные файлы не отправляются на сервер; файлы и очередь не переживают перезагрузку страницы. Настройки инструментов восстанавливаются из обычных локальных пресетов. Для предотвращения перегрузки браузера задания исполняются по одному (до 100 одновременно сохранённых в очереди).

## Точная шкала и монтаж v0.8.1

- В инструменте «Обрезка видео» появилась дополнительная временная шкала с масштабированием **1×–32×**, прокруткой, видимыми маркерами начала/конца и курсором воспроизведения.
- Границы вводятся в формате **ЧЧ:ММ:СС.мс**, до 1 миллисекунды; значения передаются напрямую в параметры экспорта. Исходная шкала с ключевыми кадрами сохранена как обзор всей длины.
- Выбор **24/25/29,97/30/50/60 FPS** регулирует шаг «±1 кадр». Это *расчётный шаг* по выбранной частоте, а не гарантия физически точного кадра для переменной частоты кадров или быстрого обрезания WebM по ключевым кадрам.
- **Отменить/Повторить** для границ обрезки и редактора субтитров, в том числе после добавления или удаления реплик. История изменений хранится в памяти текущей вкладки, не в localStorage.
- Горячие клавиши в области предпросмотра: **J/K/L** (назад на секунду/пауза/вперёд на секунду), **[ / ]** (начало/конец), **Ctrl+Z / Ctrl+Shift+Z** для истории границ; при вводе текста штатные сочетания редактора остаются за браузером.
- История накапливает не более 80 шагов, последовательные перемещения маркера группируются. Все правки удаляют устаревший результат.

## Редактор и предпросмотр

- Видео: общая Canvas-функция отрисовывает и экспортируемый видеопоток, и предпросмотр результата. Кадрирование, поворот, отражение, фильтры, размытие, подпись и разделение экрана используют одинаковую геометрию кадра.
- Переключатель «Показать исходник / Показать результат» доступен на панели предпросмотра. Качество кодирования и итоговый размер файла могут отличаться, поскольку предпросмотр не кодируется.
- Интерактивная шкала обрезки с миниатюрами, редактор SRT/VTT с правкой таймкодов и локальная аудиоволна.
- При экспорте параметры заблокированы, а устаревший файл результата удаляется после правки.

## Настройки и приватность

Параметры сохраняются **по каждому инструменту** в localStorage, восстанавливаются при следующем открытии и сбрасываются одной кнопкой. Сохраняются значения формы, **не исходные файлы**. После перезагрузки файл нужно выбрать заново.

`analytics.html` содержит только личную статистику этого браузера (до 1200 событий), экспорт и удаление. Общей аналитики, внешних серверов и отправки событий нет.

## Быстрый MP4-движок и выбор разрешения

- Из предоставленной выгрузки подключены `mp4-track-remux.js`, `mp4-copy-trim.js`, `mp4-flatten.js`, `webm-copy-trim.js`. Lokit использует их для **обрезки MP4 через edit lists**, **склейки и повтора совместимых MP4 с оригинальным звуком**, **удаления звука**, **извлечения AAC/ALAC в M4A без потерь**, **изменения скорости MP4 без аудио** и **обрезки WebM по ключевым кадрам**. Копируемые дорожки не перекодируются.
- Быстрый режим доступен при выборе **«Как у исходного видео»**. Для WebM доступна точная обрезка через обычный движок или быстрая обрезка по ключевым кадрам (начало может сдвинуться назад); выбор на форме **«Точность обрезки»**. Если MP4 не поддерживается, у ролика есть аудио при изменении скорости или требуется изменить разрешение, используется прежний Canvas/MediaRecorder. Для записи готового файла в быстром режиме не нужно воспроизводить его от начала до конца.
- Настройка **«Разрешение итогового видео»** теперь указывает качество в формате 480p/720p/1080p: число относится к меньшей стороне кадра. Например, 1920×1080 при 720p → 1280×720, а 1080×1920 → 720×1280. Размер исходника не увеличивается. По умолчанию выбран исходный размер.
- Для любых операций с видео итоговый размер отображается в панели предпросмотра. При слишком большом количестве пикселей вместо зависания выводится ошибка с предложением выбрать 1080p или 720p.
- Конвертер возвращает исходный MP4/WebM без перекодирования, когда браузер открывает файл и не запрошены изменения разрешения/FPS. В «Конвертере» и «Сжатии» автоматический режим может использовать **уже кешированный WebCodecs**; если библиотеки нет в локальном кэше, используется нативный MediaRecorder. WebCodecs/FFmpeg/WASM можно также выбрать вручную.

## Совместимость форматов и кодеков (ветка PR #2)

| Исходный контейнер и кодеки | Обработка в Lokit |
| --- | --- |
| MP4/M4V (H.264 + AAC) | Копирование, обрезка, склейка, повтор и удаление/извлечение аудио без перекодирования, если дорожки совместимы |
| MOV/QuickTime и 3GP/3G2 (H.264 + AAC) | Быстрая перепаковка в MP4 без перекодирования; часть других операций использует исходные дорожки. Несовместимые кодеки → резервное преобразование |
| MP4/MOV (H.265/HEVC, MPEG-4, ProRes, AC-3 и др.) | Исходный формат сохраняется лишь при допустимости операции; иначе используются доступные декодеры браузера либо локальный FFmpeg/WASM |
| WebM (VP8/VP9/Opus/Vorbis/AV1) | Копирование оригинала, обрезка по ключевым кадрам без перекодирования; точная обрезка и эффекты требуют кодирования |
| MKV/Matroska (H.264/H.265/VP9/AV1 и другие) | Mediabunny/WebCodecs может перепаковать поддерживаемые дорожки без перекодирования, либо преобразовать их; FFmpeg/WASM используется при невозможности открыть видео в браузере |
| AVI, WMV, FLV, MPEG/MPG, TS/MTS/M2TS, OGV | Резервная локальная обработка FFmpeg/WASM при наличии декодера для исходного кодека; поддержка зависит от сборки FFmpeg |

**Формат максимальной совместимости на выходе резервного движка:** MP4 с H.264 (YUV420p) и AAC. Кодирование — `libx264 -preset ultrafast`, чтобы снизить ожидание, хотя это может увеличивать итоговый размер. Встроенный MediaRecorder использует H.264/MP4 или VP8/WebM в зависимости от браузера.

**Резервный FFmpeg/WASM:** файл до 90 МиБ, загрузка ядра приблизительно 31 МБ при первом использовании (только библиотеки, не исходного видео), далее возможно использование офлайн при сохранённом кэше. Для файлов с неподдерживаемым браузером контейнером это срабатывает автоматически, но при первой загрузке может требоваться сеть. FFmpeg поддерживает основные одиночные операции: конвертацию, сжатие, обрезку, удаление звука, скорость, повтор, поворот, отражение, кадрирование, фильтр, размытие, громкость, извлечение аудио в M4A и кадра PNG. Для двух видеодорожек и текстовой подписи по-прежнему требуется браузерный декодер; без него выдаётся понятная ошибка вместо повреждённого результата.

**Границы совместимости:** DRM, повреждённые файлы, неизвестные аппаратные кодеки, HDR/10-bit, многодорожечные проекты, большие файлы и нестандартные временные метки нельзя гарантированно обработать каждым движком. Для профессиональных или многогигабайтных роликов нужен настольный FFmpeg.

## Скорость и выбор движка

- Для метаданных, кадра PNG и преобразования SRT/VTT полноценное перекодирование видео не требуется.
- **Если копирование дорожек невозможно**, для конвертации/сжатия при наличии кешированной библиотеки пробуется WebCodecs; для остальных операций или в отсутствие модуля работает Canvas + нативный MediaRecorder (сначала H.264/MP4 при поддержке браузера, затем VP8/WebM). Он работает во время воспроизведения; частота экспорта без явного выбора FPS по умолчанию 30. Скорость кодирования зависит от браузера и оборудования.
- WebCodecs + Mediabunny может автоматически использоваться **только из локального кэша** или при ручном выборе; FFmpeg/WASM запускается только вручную в отдельном Worker. Наличие WebCodecs не гарантирует аппаратное ускорение. При ошибке возвращаемся к нативному экспорту, не выдавая невалидные результаты за успешные.

## v0.5.1: совместимость и проверки контейнеров

- При каждой операции без перекодирования MP4 проверяется состав дорожек, наличие видеосэмплов и корректность длительности с учётом MP4 edit lists и скрытого преролла. Фрагментированные MP4 поддерживаются даже если базовый анализатор длительности возвращает 0.
- Если быстрый путь отверг файл, выполняется резервный экспорт; при невозможности инициализировать Web Audio он останавливается **с ошибкой**, а не выдаёт видео без звука.
- При остановке движения декодера более чем на 15 секунд показывается ошибка, а не бесконечный прогресс. Настоящие медленные, но продолжающиеся операции не считаются зависшими.
- CI генерирует **23 репрезентативных синтетических образца** (H.264, HEVC, MPEG-4, AAC, MP3, VP8/VP9, Opus; B-frames, VFR, 29.97 FPS, 44.1 кГц, задержка звука, фрагментированный MP4, вертикальная запись, длинный GOP, MOV, WebM) и проверяет 53 операции с независимым `ffprobe` и полным декодированием `ffmpeg`.
- Проверки не заменяют испытаний на реальных файлах с телефонов, профессиональных камер и ТВ: DRM, нестандартные метаданные, 4K/HDR и файлы многогигабайтного размера остаются вне покрытия.

Для запуска отдельно от обычных тестов:

```bash
python tests/test-formats.py
```

Требуются `ffmpeg`, `ffprobe`, Node.js 22 и Python 3. Скрипт создаёт исходники в `tests/fixtures/generated/`, который не добавляется в Git.

## v0.8.2 — устойчивость медиаэкспорта

- Исправлено освобождение видеодекодера и временного `blob:` URL при ошибке открытия файла.

Это не заменяет испытаний на физических Android/iOS, 4K HDR и многогигабайтных пользовательских файлах.

## v0.7.0: экспериментальные видеодвижки

Начиная с v0.7.0 в **Конвертере видео** и **Сжатии видео** доступны WebCodecs и FFmpeg/WASM. Теперь по умолчанию выбран **автоматический режим**: WebCodecs разрешён из заранее сохранённого кэша, а при его отсутствии используется встроенный браузерный MediaRecorder. Оба движка можно выбрать вручную:

- **WebCodecs + Mediabunny 1.65.2**: извлечение дорожек, аппаратное декодирование/кодирование (если доступно в браузере) и упаковка MP4 в одном конвейере; перед сохранением проверяется, что число аудио/видеодорожек не уменьшилось. Если кодек/браузер не поддерживается, включается обычный Canvas/MediaRecorder.
- **FFmpeg/WASM single-thread**: отдельный Worker с однопоточным ядром @ffmpeg/core 0.12.10 (~31 МБ). Ограничен файлами до 90 МиБ, время выполнения ограничено 6 минутами. Отмена завершает Worker и освобождает память. При ошибке используется исходный движок. В отличие от многопоточного FFmpeg, не требует SharedArrayBuffer и специальных HTTP-заголовков.

Дополнительные библиотеки загружаются по HTTPS **только при явном выборе** режима из закреплённых URL jsDelivr и кешируются в Cache Storage браузера. При следующем запуске они могут работать офлайн, если браузер сохранил кеш; **первый запуск требует интернета**. Исходные видео и результаты не отправляются на CDN. Локальная аналитика не отправляется на сервер. Пользователь может очистить загруженные модули, удалив данные сайта.

Важное ограничение: экспериментальные движки предназначены **только для конвертера и сжатия**, не обещают ускорение для всех устройств и не заменяют быстрые операции MP4/WebM без перекодирования. WebCodecs требует аппаратной/программной поддержки нужных кодеков в браузере; FFmpeg/WASM может работать медленнее и расходовать много памяти. Версия с однопоточным ядром тестируется отдельно от классического экспорта.

Версии и источники: [Mediabunny](https://github.com/Vanilagy/mediabunny/releases/tag/v1.65.2) (MPL-2.0), [ffmpeg.wasm](https://github.com/ffmpegwasm/ffmpeg.wasm) (MIT для обвязки; лицензии кодеков FFmpeg могут отличаться). Зависимости не включены в исходные файлы Lokit; загрузка выполняется в браузере по запросу.

## v0.8.1 — полноценные монтажные дорожки

- Склейка: наглядная последовательность двух клипов и переключение порядка; порядок применяется к быстрому MP4 и резервному кодеру.
- Разделённый экран: две дорожки с задержкой начала второго видео. Задержка учитывается в предпросмотре, общей длительности и Canvas-экспорте.
- Скорость и повторы: наглядное отображение итоговой длительности и сегментов повтора.
- Кадр из видео: положение курсора обновляет таймкод экспортируемого PNG с миллисекундами.
- Аудио: декодирование волны, когда доступно; для больших видео или неподдерживаемого контейнера — живая осциллограмма через Web Audio.
- Субтитры: графические блоки и редактирование их начала, конца и положения; изменения попадают в SRT/VTT и историю отмены.
- Кадрирование: границы можно двигать за угловые маркеры в режиме «Показать исходник».
- Экран/камера: предпросмотр с разрешения пользователя и индикатор уровня микрофона во время записи; после остановки все дорожки освобождаются.

Обратите внимание: это монтажные функции существующих инструментов, **не** многослойный NLE с произвольным количеством видеодорожек. Обработка остаётся локальной.
