# Lokit — браузерные инструменты и аналитика

24 самостоятельных инструмента для видео, аудио, субтитров и записи экрана, без сторонних библиотек и передачи пользовательских файлов на сервер. Тёмная тема, адаптивная сетка, понятная индикация обработки, работа офлайн через PWA.

В проект включён **модуль аналитики** на отдельной странице `analytics.html`:

- **Личная статистика:** хранится только в localStorage текущего браузера. Считает просмотры, открытия инструментов, успешные операции, ошибки, отмены, длительность и суммарные объёмы файлов. Доступны периоды 7/30/90 дней, график, таблица, история последних событий, экспорт в JSON и удаление.
- **Общая статистика:** собирается опциональным сервером Cloudflare Workers + D1, также доступна на `analytics.html`. Это агрегаты событий со всех браузеров, подключённых к **одному** endpoint. Публичные показатели не являются числом уникальных посетителей.
- **Приватность:** ни личная, ни общая аналитика не анализируют содержимое файлов. На сервер **не отправляются** файлы, имена, пути, тексты субтитров, поисковые запросы, ошибки или идентификаторы пользователей; отдельные события содержат тип действия, ID инструмента, длительность и объёмы. В Worker сохраняется случайный идентификатор *события* для защиты от повторов, не идентификатор посетителя. Включение передачи событий требует явного согласия на странице аналитики; первоначально она выключена. Тексты ошибок не записываются даже в локальную аналитику.
- **Офлайн:** личная статистика работает без интернета; события общей статистики могут накапливаться в локальной очереди (не больше 150 событий, не старше ~7 дней) и отправляются при восстановлении сети, только если сбор разрешён. Сервер недоступен — показывается сообщение, а не вымышленные данные.

## 1. Публикация сайта на GitHub Pages

1. Создайте репозиторий `lokit`.
2. Опубликуйте исходники в `main`. GitHub Actions автоматически запускает модульные и браузерные проверки и затем публикует статическую часть сайта.
3. При первом запуске выберите `Settings → Pages → Build and deployment → Source: GitHub Actions` (если страница ещё не активирована).
4. Сайт: `https://teenkode.github.io/lokit/` (для аккаунта `TeenKode`), личная статистика: `https://teenkode.github.io/lokit/analytics.html`.
5. Загрузите страницы онлайн один раз, затем сервис-воркер кеширует HTML, CSS, JS и иконки для автономного запуска.

Всё перечисленное работает без Cloudflare. До развёртывания API **общая статистика будет показывать «не подключена»**.

## 2. Подключение общей статистики: Cloudflare Workers + D1

Нужен аккаунт Cloudflare и установленный Node.js. Workers и D1 имеют бесплатные лимиты, но наличие бесплатного тарифа и квоты следует проверить перед запуском.

```bash
cd analytics-worker
npx wrangler login
npx wrangler d1 create lokit-analytics
```

Cloudflare покажет `database_id`. Скопируйте его в `analytics-worker/wrangler.toml` вместо `REPLACE_WITH_YOUR_D1_DATABASE_UUID`.

В `wrangler.toml` укажите `ALLOWED_ORIGIN` — **только origin**, без пути. Для `https://teenkode.github.io/lokit/` это `https://teenkode.github.io`.

```bash
npx wrangler d1 migrations apply lokit-analytics --remote
npx wrangler deploy
```

Wrangler выведет адрес вида `https://lokit-analytics.YOUR-SUBDOMAIN.workers.dev`. Впишите его в `js/analytics-config.js`:

```js
export const GLOBAL_ANALYTICS_URL = 'https://lokit-analytics.YOUR-SUBDOMAIN.workers.dev';
```

Закоммитьте и опубликуйте эти изменения на GitHub Pages. После обновления PWA обе страницы Lokit станут получать общую статистику с сервера. Передача анонимных событий по умолчанию **выключена**. Чтобы участвовать в общей статистике, посетитель должен явно включить переключатель на странице аналитики. Уже сохранённый выбор пользователя сохраняется при обновлении. **Ранее отправленные агрегированные показатели при локальном удалении не исчезают.**

Запуск для локальных тестов:

```bash
cd analytics-worker
npx wrangler d1 migrations apply lokit-analytics --local
npx wrangler dev
```

Для фронтенда можно временно указать `http://localhost:8787` в `js/analytics-config.js` (разрешён только локально). При этом `ALLOWED_ORIGIN` на Worker должен точно совпадать с origin тестовой страницы.

### Важные ограничения общей аналитики

- GitHub Pages **сам по себе** не может хранить общие счётчики. Без отдельного Worker общая статистика недоступна.
- В Worker настроен ежедневный Cron Trigger в 03:00 UTC: события, полученные более 90 дней назад, удаляются из D1. Задача начнёт действовать только **после развёртывания Worker** и применения миграции `0002_retention_index.sql`; проверяйте выполнение Cron и объём базы в аккаунте Cloudflare.
- HTTP Origin/CORS — не защита от целенаправленной подделки запросов; открытый API можно атаковать. Для публичного сайта настройте Rate Limiting / WAF Cloudflare на `/api/events`, мониторинг и при необходимости дополнительные средства антибот-защиты.
- Не собираются cookies или постоянные ID пользователей, поэтому **число уникальных посетителей не вычисляется**. Просмотры сайта — это просмотры, а не люди.
- IP-адрес доступен на сетевом уровне Cloudflare, но код Worker его не сохраняет. Отредактируйте публичную политику конфиденциальности с учётом используемого хостинга и местных правил.
- Локальная история ограничена 1200 событиями; очередь отправки ограничена 150 событиями. Передача событий выключена до согласия пользователя. При отказе от участия очередь очищается, а текущий сетевой запрос отменяется, если браузер ещё не закончил его. Уже принятые сервером данные нельзя удалить через локальную кнопку. Периоды графиков считаются по календарным дням UTC, а даты событий в истории отображаются в часовом поясе устройства.

Официальная документация: https://developers.cloudflare.com/d1/get-started/ и https://developers.cloudflare.com/workers/wrangler/commands/d1/.

## Устройство проекта

- `index.html`, `style.css`, `js/app.js` — главная страница, интерфейс и прогресс операций.
- `js/tools.js`, `js/media.js` — инструменты и локальный медиа-движок.
- `analytics.html`, `js/analytics-page.js` — страница отчётов.
- `js/analytics.js`, `js/analytics-config.js` — событийная аналитика, очередь, приватность, конфигурация общего API.
- `analytics-worker/` — разворачиваемый отдельно backend статистики.
- `sw.js`, `manifest.webmanifest`, `icons/` — PWA.
- `tests/` — проверки.

## 3. Проверки перед публикацией

В рабочем каталоге исходников:

```bash
node tests/test-tools.mjs
node tests/test-media.mjs
node tests/test-analytics.mjs
node tests/test-worker.mjs
python tests/test-sql.py
python tests/test-structure.py
```

Для сквозного тестирования интерфейса отдельно требуется установленный Chromium и Playwright. Скрипт `python tests/test-browser.py` проверяет страницу и экспорт субтитров; некоторые среды запрещают браузеру доступ даже к `localhost`. В таком случае это ограничение тестового окружения, а не положительный результат проверки.

Обновление PWA: при изменении списка ресурсов/версии приложения повышайте имя `CACHE` в `sw.js`. В этой сборке используется `lokit-v6`.

## Ограничения медиаобработки

Видео преобразуется через браузерные Canvas / Web Audio / MediaRecorder, обычно в WebM и в реальном времени. Форматы, качество, скорость, поддержка кодеков и запись экрана зависят от браузера и устройства. Не сворачивайте вкладку во время видеоэкспорта. Для записи требуется HTTPS или localhost и разрешение браузера.

Этот сайт и скрипты написаны самостоятельно и не включают исходные сторонние страницы.


## Автоматические проверки на GitHub

Файл `.github/workflows/publish.yml` запускает модульные, SQL и браузерные тесты на каждый push в `main`. Если тесты успешны, публикует сайт через GitHub Pages и проверяет основные HTTP-ресурсы опубликованного сайта. Снимки тестов сохраняются как Actions artifact. Сервер аналитики (`analytics-worker/`) на Pages не публикуется; для него требуется отдельное развёртывание в Cloudflare.
