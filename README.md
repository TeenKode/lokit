# Lokit v0.8.5 beta — локальные инструменты

25 инструментов для видео, аудио, PDF, субтитров, записи экрана и кадров. Сайт работает на GitHub Pages и сохраняет интерфейс офлайн.

## PDF-редактор на базе PDFCraft

В каталоге появилась группа «PDF»: полноценный браузерный PDF-редактор
открывается на странице [pdf.html](pdf.html). В нём работает оригинальная
сборка PDFCraft на WebAssembly, включая просмотр, поиск, страницы,
объединение, разделение, аннотации, формы и доступные веб-функции OCR.
Файлы остаются на устройстве. Для работы без интернета есть отдельная
кнопка сохранения движка и моделей распознавания.

PDFCraft распространяется и обновляется отдельно от Lokit. Готовая
сборка проверяется по SHA-256 и включается в GitHub Pages при публикации;
исходный git-репозиторий не хранит двоичные файлы PDFCraft. В Settings →
Pages необходимо выбрать публикацию через GitHub Actions.

Подробнее: [архитектура, лицензии, ограничения и установка](docs/pdfcraft-integration.md).
В браузере поддерживается функциональность веб-версии, а не все
десктопные функции и не CLI/MCP.

## Меню инструментов v0.8.4

Инструменты собраны в **постоянной левой панели** на компьютере: группы «Видео», «Аудио», «Изображения», «Субтитры», «Запись», «Анализ», «PDF» можно сворачивать. Поиск фильтрует инструменты по названию и описанию, есть переключатель «Все / Избранное».

Рядом с каждым инструментом — отдельная кнопка-звёздочка: она появляется при наведении или переходе с клавиатуры; на сенсорных устройствах видна всегда. Избранное хранится только в локальном браузере. При выборе инструмента основной экран показывает рабочую область, не дублируя каталог. На узких экранах меню открывается кнопкой в шапке и закрывается выбором инструмента, фоном, кнопкой закрытия или Escape.

## Пакетная обработка v0.6.0

Отдельная страница `batch.html` позволяет создать **общую очередь заданий для разных инструментов**, выбрать много файлов, задать параметры каждой группы и запустить последовательную обработку. Инструменты, которым нужны два файла, берут их парами в выбранном порядке. Запись камеры и экрана остаётся в обычном режиме.

У каждого задания видны состояние, процент (если его сообщает обработчик) и кнопка отмены. Общий процент считается **по числу заданий, а не по байтам**; при отсутствии прогресса отдельного инструмента его индикатор неопределённый. Есть пауза после текущего файла, отмена очереди, повтор ошибок и скачивание результатов по отдельности или одним ZIP.

ZIP создаётся прямо в браузере без внешнего CDN и без повторного сжатия видео, CRC32 рассчитывается блоками. Поддерживается формат ZIP32 до 4 ГБ. Выходные файлы не отправляются на сервер; файлы и очередь не переживают перезагрузку страницы. Настройки инструментов восстанавливаются из обычных локальных пресетов. Для предотвращения перегрузки браузера задания исполняются по одному (до 100 одновременно сохранённых в очереди).

## Точная шкала и монтаж v0.8.1

- В инструменте «Обрезка видео» появилась дополнительная временная шкала с масштабированием **1×–32×**, прокруткой, видимыми маркерами начала/конца и курсором воспроизведения.
- Границы вводятся в формате **ЧЧ:ММ:СС.мс**, до 1 миллисекунды; значения передаются напрямую в параметры экспорта. Исходная шкала с ключевыми кадрами сохранена как обзор всей длины.
- Выбор **24/25/29,97/30/50/60 FPS** регулирует шаг «±1 кадр». Это *расчётный шаг* по выбранной частоте, а не гарантия физически точного кадра для переменной частоты кадров или быстрого обрезания WebM по ключевым кадрам.
- **Отменить/Повторить** для границ обрезки и редактора субтитров, в том числе после добавления или удаления реплик. История изменений хранится в памяти текущей вкладки, не в localStorage.
- Горячие клавиши в области предпросмотра: **J/K/L** (назад на секунду/пауза/вперёд на секунду), **[ / ]** (начало/конец), **Ctrl+Z / Ctrl+Shift+Z** для истории границ; при вводе текста штатные сочетания редактора остаются за браузером.
- История накапливает не более 80 шагов, последовательные перемещения маркера группируются. Все правки удаляют устаревший результат.

## Редактор и предпросмотр

- Видео: общая Canvas-функция отрисовывает и экспортируемый видеопоток, и предпросмотр результата. Кадрирование, поворот, отражение, фильтры, размытие, подпись и разделение экрана используют одинаковую геометрию кадра.
- Переключатель «Показать исходник / Показать результат» доступен на панели предпросмотра. Качество кодирования и итоговый размер файла могут отличаться, поскольку предпросмотр не кодируется.
- Интерактивная шкала обрезки с миниатюрами, редактор SRT/VTT с правкой таймкодов и локальная аудиоволна.
- При экспорте параметры заблокированы, а устаревший файл результата удаляется после правки.

## Настройки и приватность

Параметры сохраняются **по каждому инструменту** в localStorage, восстанавливаются при следующем открытии и сбрасываются одной кнопкой. Сохраняются значения формы, **не исходные файлы**. После перезагрузки файл нужно выбрать заново.

`analytics.html` содержит только личную статистику этого браузера (до 1200 событий), экспорт и удаление. Общей аналитики, внешних серверов и отправки событий нет.

## Быстрый MP4-движок и выбор разрешения

- Из предоставленной выгрузки подключены `mp4-track-remux.js`, `mp4-copy-trim.js`, `mp4-flatten.js`, `webm-copy-trim.js`. Lokit использует их для **обрезки MP4 с исходными дорожками и точным временем через edit lists**, **склейки совместимых MP4**, **удаления звука**, **изменения скорости MP4 без аудио** и **обрезки WebM по ключевым кадрам** без перекодирования видеопотока. Видеодорожка и качество сохраняются.
- Быстрый режим доступен при выборе **«Как у исходного видео»**. Для WebM доступна точная обрезка через обычный движок или быстрая обрезка по ключевым кадрам (начало может сдвинуться назад); выбор на форме **«Точность обрезки»**. Если MP4 не поддерживается, у ролика есть аудио при изменении скорости или требуется изменить разрешение, используется прежний Canvas/MediaRecorder. Для записи готового файла в быстром режиме не нужно воспроизводить его от начала до конца.
- Настройка **«Разрешение итогового видео»** теперь указывает качество в формате 480p/720p/1080p: число относится к меньшей стороне кадра. Например, 1920×1080 при 720p → 1280×720, а 1080×1920 → 720×1280. Размер исходника не увеличивается. По умолчанию выбран исходный размер.
- Для любых операций с видео итоговый размер отображается в панели предпросмотра. При слишком большом количестве пикселей вместо зависания выводится ошибка с предложением выбрать 1080p или 720p.
- В «Конвертере» и «Сжатии» есть опциональные движки WebCodecs и FFmpeg/WASM v0.7.0. Они загружают дополнительные библиотеки только по выбору пользователя и сохраняют резервный экспорт. В остальных операциях непроверенные движки не подменяют рабочий код.

## Расширенная поддержка видеокодеков и резервный FFmpeg/WASM

Lokit работает с MP4/M4V, MOV/QuickTime, 3GP, WebM, MKV, AVI, WMV, FLV, MPEG/MPG, TS/MTS/M2TS и OGV, если исходный видеокодек доступен браузеру или встроенному FFmpeg/WASM. Файлы обрабатываются локально.

- **Без перекодирования, где возможно:** MP4/WebM, быстрые операции с совместимыми дорожками H.264/AAC, обрезка, повтор, объединение MP4, извлечение AAC в M4A. Для некоторых MOV/3GP выполняется перепаковка в MP4 без изменения кодека.
- **Несовместимые исходники:** при невозможности открыть файл встроенным декодером подключается FFmpeg/WASM, размещённый вместе с сайтом. MP4-результат содержит H.264/YUV420p и AAC, с быстрым кодированием `ultrafast`.
- **Склейка двух видео:** несовместимые клипы приводятся к общему размеру, 30 FPS, H.264 и AAC. При отсутствии аудиодорожки добавляется тишина. Затем результат склеивается с `-c copy`; выбранный порядок клипов сохраняется.
- **Разделённый экран и стереопара:** резервный FFmpeg/WASM совмещает видеодорожки; разделённый экран учитывает задержку второго ролика и использует звук первого.
- **Текстовая подпись:** браузер создаёт прозрачный PNG с текстом, в том числе кириллицей; FFmpeg накладывает изображение, поэтому не требует шрифтов или `drawtext`.
- **Проверка:** unit-тесты операций, проверка результатов настоящим FFmpeg/FFprobe и дополнительный браузерный тест исполнения реального FFmpeg/WASM с локальными файлами.

**Ограничения:** для FFmpeg/WASM суммарный размер исходников до 90 МиБ; обработка однопоточная и потребляет память. Поддержка кодеков зависит от комплектной сборки FFmpeg, DRM/HDR/10-bit и большие проекты не гарантируются. Исходные видео не отправляются на сервер. Дополнительные видеомодули размещены на том же домене, их можно предварительно сохранить для офлайн-работы.

## Скорость и выбор движка

- Для метаданных, кадра PNG и преобразования SRT/VTT полноценное перекодирование видео не требуется.
- **Если быстрая операция с MP4 невозможна**, видеоэкспорт выполняется через Canvas + MediaRecorder, как правило в WebM, в реальном времени. Начиная с версии 0.4 обновление Canvas-потока лучше привязано к декодированным кадрам через `requestVideoFrameCallback`; когда браузер не поддерживает его, используется ограниченный таймер. Это **не ускоряет перекодирование сверх реального времени**.
- Экспериментальный WebCodecs-экспорт использует контейнерный модуль, а FFmpeg/WASM запускается в отдельном Worker. Экспериментальные движки не выбираются автоматически, имеют ограничения по форматам и размеру входа, а при сбоях используется обычный безопасный экспорт.

## v0.5.1: совместимость и проверки контейнеров

- При каждой операции без перекодирования MP4 проверяется состав дорожек, наличие видеосэмплов и корректность длительности с учётом MP4 edit lists и скрытого преролла. Фрагментированные MP4 поддерживаются даже если базовый анализатор длительности возвращает 0.
- Если быстрый путь отверг файл, выполняется резервный экспорт; при невозможности инициализировать Web Audio он останавливается **с ошибкой**, а не выдаёт видео без звука.
- При остановке движения декодера более чем на 15 секунд показывается ошибка, а не бесконечный прогресс. Настоящие медленные, но продолжающиеся операции не считаются зависшими.
- CI генерирует **23 репрезентативных синтетических образца** (H.264, HEVC, MPEG-4, AAC, MP3, VP8/VP9, Opus; B-frames, VFR, 29.97 FPS, 44.1 кГц, задержка звука, фрагментированный MP4, вертикальная запись, длинный GOP, MOV, WebM) и проверяет 53 операции с независимым `ffprobe` и полным декодированием `ffmpeg`.
- Проверки не заменяют испытаний на реальных файлах с телефонов, профессиональных камер и ТВ: DRM, нестандартные метаданные, 4K/HDR и файлы многогигабайтного размера остаются вне покрытия.

Для запуска отдельно от обычных тестов:

```bash
python tests/test-formats.py
```

Требуются `ffmpeg`, `ffprobe`, Node.js 22 и Python 3. Скрипт создаёт исходники в `tests/fixtures/generated/`, который не добавляется в Git.

## v0.8.2 — надёжность и обработка ошибок

- Исправлено освобождение декодера и `blob:` URL при ошибке открытия видео. Повторное закрытие безопасно.
- Ожидающие `play()`, запуск аудио, запись результата, извлечение звука и создание PNG теперь поддерживают отмену и ограничение времени ожидания. Продолжающийся позже системный Promise не вызывает необработанную ошибку.
- При внезапной остановке или ошибке MediaRecorder запись не остаётся в бесконечном ожидании кнопки «Стоп»: камера, микрофон и предпросмотр освобождаются.
- При разделении экрана зависание **каждого** видеодекодера отслеживается отдельно. Раньше движущийся общий таймер скрывал зависший источник. Для скорости видео расчёт итоговой длительности учитывает выбранную скорость воспроизведения.
- Регрессионные тесты дополнены повреждёнными и обрезанными MP4/WebM, отменой медиаопераций, неожиданным завершением записи, восстановлением после ошибки и проверкой длинного (12 с) и 60 FPS образцов.
- В тестовом наборе теперь **23 синтетических образца реальных контейнеров и кодеков, 53 сценария, 47 успешных быстрых результатов**, подтверждённых FFprobe и полным декодированием FFmpeg. Синтетические записи не заменяют пользовательские 4K/HDR или длительные мобильные видео.

## v0.7.0: экспериментальные видеодвижки

В **Конвертере видео** и **Сжатии видео** появилось поле «Движок экспорта». По умолчанию выбран **обычный локальный экспорт**, который не требует внешних библиотек. Доступны два режима, запускаемые **только по выбору пользователя**:

- **WebCodecs + Mediabunny 1.65.2**: извлечение дорожек, аппаратное декодирование/кодирование (если доступно в браузере) и упаковка MP4 в одном конвейере; перед сохранением проверяется, что число аудио/видеодорожек не уменьшилось. Если кодек/браузер не поддерживается, включается обычный Canvas/MediaRecorder.
- **FFmpeg/WASM single-thread**: отдельный Worker с однопоточным ядром @ffmpeg/core 0.12.10 (~31 МБ). Ограничен файлами до 90 МиБ, время выполнения ограничено 6 минутами. Отмена завершает Worker и освобождает память. При ошибке используется исходный движок. В отличие от многопоточного FFmpeg, не требует SharedArrayBuffer и специальных HTTP-заголовков.

Дополнительные библиотеки загружаются по HTTPS **только при явном выборе** режима из закреплённых локальных адресов Lokit и кешируются в Cache Storage браузера. При следующем запуске они могут работать офлайн, если браузер сохранил кеш; **для первой загрузки требуется доступ к сайту Lokit**. Исходные видео и результаты не отправляются на CDN. Локальная аналитика не отправляется на сервер. Пользователь может очистить загруженные модули, удалив данные сайта.

Важное ограничение: экспериментальные движки предназначены **только для конвертера и сжатия**, не обещают ускорение для всех устройств и не заменяют быстрые операции MP4/WebM без перекодирования. WebCodecs требует аппаратной/программной поддержки нужных кодеков в браузере; FFmpeg/WASM может работать медленнее и расходовать много памяти. Версия с однопоточным ядром тестируется отдельно от классического экспорта.

Версии и источники: [Mediabunny](https://github.com/Vanilagy/mediabunny/releases/tag/v1.65.2) (MPL-2.0), [ffmpeg.wasm](https://github.com/ffmpegwasm/ffmpeg.wasm) (MIT для обвязки; лицензии кодеков FFmpeg могут отличаться). Зависимости не включены в исходные файлы Lokit; загрузка выполняется в браузере по запросу.

## v0.8.1 — полноценные монтажные дорожки

- Склейка: наглядная последовательность двух клипов и переключение порядка; порядок применяется к быстрому MP4 и резервному кодеру.
- Разделённый экран: две дорожки с задержкой начала второго видео. Задержка учитывается в предпросмотре, общей длительности и Canvas-экспорте.
- Скорость и повторы: наглядное отображение итоговой длительности и сегментов повтора.
- Кадр из видео: положение курсора обновляет таймкод экспортируемого PNG с миллисекундами.
- Аудио: декодирование волны, когда доступно; для больших видео или неподдерживаемого контейнера — живая осциллограмма через Web Audio.
- Субтитры: графические блоки и редактирование их начала, конца и положения; изменения попадают в SRT/VTT и историю отмены.
- Кадрирование: границы можно двигать за угловые маркеры в режиме «Показать исходник».
- Экран/камера: предпросмотр с разрешения пользователя и индикатор уровня микрофона во время записи; после остановки все дорожки освобождаются.

Обратите внимание: это монтажные функции существующих инструментов, **не** многослойный NLE с произвольным количеством видеодорожек. Обработка остаётся локальной.

## v0.8.3 — адаптивная компоновка

- Компактная шапка (даже на ширине 320 px), горизонтально прокручиваемая навигация и категории без горизонтального переполнения страницы.
- Статистика в одну строку на мобильном экране; компактнее блок приветствия, карточки инструментов и нижние информационные разделы.
- Загрузка файла перенесена в основной столбец рядом с предпросмотром, а настройки и действия собраны в соседнюю панель.
- Таймлайны, список реплик, кнопки и поля адаптированы для маленьких экранов без обрезки маркеров.
- Пакетная обработка и страницы статистики используют те же принципы отступов и ширины.
- Сквозная адаптивная проверка `python tests/test-layout.py` прогоняет 320, 390, 768, 1024 и 1440 px с реальными файлами и экспортными интерфейсами.

На мобильном экране навигация и категории прокручиваются горизонтально *внутри своих полос*; вся страница по горизонтали не прокручивается. Файлы не передаются на сервер.

## v0.8.5 — автономные движки и офлайн-пакет

- FFmpeg/WASM 0.12.10 (один поток) и Mediabunny 1.65.2 публикуются в `assets/codecs/` **на том же домене, что и Lokit**. В работающем сайте нет запросов к CDN. Обычные инструменты не скачивают эти библиотеки, пока пользователь не выбрал экспериментальный движок.
- Сборка: `npm install --ignore-scripts`, затем `npm run vendor-codecs`. Скрипт берёт закреплённые npm-дистрибутивы, копирует JS/WASM и пишет `assets/codecs/manifest.json` с размерами и SHA-256. GitHub Actions автоматически добавляет эти файлы в `main` после принятия изменений; GitHub Pages продолжает обслуживать корень репозитория, без изменения способа публикации.
- В меню **Офлайн-движки** на странице «Что нового» можно скачать все три ресурса в Cache Storage, проверить полноту загрузки или удалить данные. Повторная загрузка не требуется, пока браузер хранит кеш. Для использования без сети также нужно хотя бы раз открыть сам сайт, чтобы Service Worker сохранил оболочку.
- В отличие от локального комплекта, многопоточный FFmpeg не включён: GitHub Pages по умолчанию не управляет заголовками изоляции браузера. Поддержка конкретных кодеков и ограничения обработки остаются прежними.
- Самостоятельный выпуск: `npm install --ignore-scripts && npm run vendor-codecs && npm test`; теговые ZIP-релизы содержат `assets/codecs/`.
